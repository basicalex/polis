# UI audit and improvement plan, 2026-09-08

Source of rules: `docs/design/ui-playbook-checklist.md` (codes H/C/L/K/D/P/T/I/S/B).
Contract that still wins on conflict: `DESIGN.md`. The playbook's glass,
shadow-for-depth, and overlapping-image tips are not applied; the light civic
world, trace line, meaning model, and privacy rules are unchanged.

Baseline screenshots: scratchpad `shots-before/` (local dark theme) and
`shots-before-public/` (public release). Inventory from a full read of
`apps/web/src`, `packages/ui/src`, and `DESIGN.md`.

## Findings

Ordered by how much of the UI each one touches.

- F1 Three drifting token sets. `packages/ui/src/styles/base.css`,
  `apps/web/src/styles.css`, and `apps/web/src/styles/pilot/vrsar.css` each
  define palettes with different values (warning `#9a6700` vs `#8a5d00`,
  radii `4px/8px` vs `0.25rem/0.5rem`, `--type-body` documented but never
  defined, spacing scale 6/12/20/32/52px not on a 4px grid). The pilot shell
  sets `data-theme="pilot-light"`, which matches no theme block. Rules L3,
  K1, K6, P3.
- F2 Four button systems and no primary/secondary/tertiary contract. Bare
  `button`, `.release-button`, `.pilot-button`, and demo-local classes differ
  in padding, radius, and disabled treatment. On `/verify` three mode tabs,
  the file chooser, and the drop zone all compete at equal weight. Rules H2,
  K2, I1.
- F3 Five status-label systems (`.trust-badge`, `.badge-*`, `.meaning-label`,
  `.demo-stamp`, `.pilot-status`), two of them boxed and filled against the
  contract. The yellow `DEMONSTRATION FIXTURE` label on citizen cards is
  louder than the record date it sits beside. Rules H1, K6, P1, P4.
- F4 2888 lines of page-local `<style>`, more than the shared stylesheets
  combined. `index.astro` and `hr/index.astro` carry 152 identical lines;
  `demo/official.astro` and `demo/review.astro` each define 33 `.queue-*`
  selectors that overlap and drift. Rule K6.
- F5 Local navigation is 13 flat links with no grouping; on a 390px phone it
  wraps to four rows and pushes the page title below the fold. Rules S3, I2,
  L9.
- F6 Empty states are bare sentences ("No issues yet.") with no purpose line,
  tips, or action. No shared component exists. Rule S1.
- F7 Proximity failures: lede paragraphs touch the panel below them on
  `/issues`, `/verify`, `/proofs`; the `/login` email field renders as an
  unstyled browser input because `input[type=email]` has no rule; pilot
  login repeats "Testna adresa e-pošte" as both heading and label. Rules
  H6, C1, I5.
- F8 Measure and width: `/transparency` prose runs past 110 characters per
  line inside a 94rem column; `/verify`, `/proofs`, `/login` stretch a
  single form across 1440px with content in the left third. Rules L5, L6.
- F9 Detail panels (demo review, demo official, record) render every field as
  equal-weight label:value rows. The commitment text and due date, the two
  things a reviewer reads first, get the same treatment as "Category".
  Rules H3, H5.
- F10 Card and panel recipes differ across `.panel`, `.demo-panel`,
  `.pilot-panel`, `.verdict-card`, and page-local panels (padding 1rem vs
  1.25rem, nested bordered panels on `/verify`). Rules K6, D5, D6.
- F11 Form coverage: `email`, `password`, `date`, `number`, `select`,
  `checkbox`, `radio` fall back to browser defaults outside the pilot; three
  parallel field systems exist; no shared inline-validation pattern. Rules
  I5, I6, K6.
- F12 Local dark theme still uses the retired Barlow Condensed display face
  and border-only hierarchy that `DESIGN.md` rejected. It is not the shipped
  world but it is what every developer and screenshot sees. Rules T1, D5.
- F13 Skip link targets `#public-record`, which exists only on the two
  landing pages; `<main>` is `#main-content`. Accessibility gate 5.
- F14 Public release specifics: the light world already follows most of
  the playbook. Remaining gaps are `/transparency` nesting bordered panels
  inside bordered panels with headings, lists, and links at near-equal
  weight; the fixture label on demo rows louder than the date; the review
  detail column stacking six blocks with no grouping; and the citizen
  primary action sitting under the list instead of beside the title.
  Rules D5, H1, H7, I1.
- F15 No automated contrast check, no visual-regression baseline, no test
  asserts a CSS property. Rule D1 is unverified today.

## Decisions

- D1 One token source: `packages/ui/src/styles/base.css` becomes the only
  place tokens are defined. Light is the default `:root`; dark is
  `[data-theme='dark']` only. `apps/web/src/styles.css` and `vrsar.css` stop
  redefining tokens. `DESIGN.md` values are canonical.
- D2 Spacing moves to a 4px ladder `--space-1` (0.25rem) through `--space-16`
  (4rem). The old names stay as aliases: xs 0.5rem, sm 0.75rem, md 1.25rem,
  lg 2rem, xl 3rem. `DESIGN.md` layout section is updated to match.
- D3 One radius scale (`--radius-sm` 0.25rem, `--radius-md` 0.5rem,
  `--radius-pill`), one shadow scale (`--shadow-1/2/3`, tinted with the ink
  color at low alpha), used only for overlays per the contract.
- D4 One button contract: `.btn` with `data-variant="primary|secondary|
  tertiary|danger"`, 2.75rem min target, one radius, disabled state with
  text reason. All four existing systems become aliases or are deleted.
- D5 One status label: `.status-label` (unboxed, sans, per contract) plus
  `.status-label[data-style="stamp"]` for the locked demo chrome. Others
  removed.
- D6 One panel recipe, one field recipe (`.field` with label, control, hint,
  error), one empty-state component (`EmptyState.astro`: purpose, up to
  three tips, one action), one page-header recipe (title, institution line,
  lede with fixed gaps).
- D7 Prose measure 68ch enforced by a `.prose` class; single-form pages
  constrain the form to 36rem and center it.
- D8 The dark local theme is not redesigned. It inherits the same components
  and tokens; Barlow Condensed is dropped so both worlds share one display
  face.

## Waves

Each wave is one packet to one Opus frontend agent unless noted. Every
packet cites the checklist codes it must satisfy and ends with `bun run
--filter @polis/apps-web test`, `bun run --filter @polis/apps-web typecheck`,
and a screenshot pass.

- W0 Foundation (blocking, one agent): D1 through D6 in `packages/ui` and
  `apps/web/src/styles.css`; no page markup changes beyond class renames
  needed to keep pages rendering. Update `DESIGN.md` tables.
- W1 Chrome (after W0): `Base.astro` nav grouped into four groups with a
  disclosure menu on phone, skip-link fix, footer, banner spacing.
- W2 Public reading surfaces (after W0, parallel with W1, W3, W4): `/`,
  `/hr` (shared component, one style source), `/transparency`, `/source`,
  `/docs`, `/methodology`, `/privacy`, `/security`: prose measure, section
  rhythm, heading scale, one primary action per page.
- W3 Demo surfaces (after W0): extract queue CSS to a shared stylesheet,
  detail panel hierarchy (commitment and due date first, values louder than
  labels), quieter fixture label, empty states, field recipe, thumb-zone
  primary action on phone.
- W4 Pilot Vrsar (after W0): drop the duplicate palette, adopt shared
  button/field/panel/status recipes, simplify login, error state per S2,
  receipts list rows.
- W5 Task pages (after W0): `/verify`, `/proofs`, `/login`, `/issues`,
  `/assistant`, `/partners`, `/pilot/results`, contribute pages: constrained
  form width, one primary action, empty states, remove page-local styles.
- W6 QA (after W1-W5, one agent): contrast checker script over computed
  styles for every route at both themes, after-screenshots into the
  scratchpad, diff against baseline, report per checklist code.

Stylesheet ownership during W1-W5: `apps/web/src/styles.css` is frozen.
Each wave writes its CSS into its own file under `apps/web/src/styles/`
(`chrome.css`, `public.css`, `demo.css`, `tasks.css`; the pilot keeps
`pilot/vrsar.css`) imported from the layout or page frontmatter, and lists
the blocks in `styles.css` that became dead. W6 deletes the dead blocks in
one pass.

Verification and commits stay with the orchestrating session.

Files below are the ones that carry the fix.

### Reproducing

Local (dark) world:

```
cd apps/web && bunx astro dev --port 4397 --host 127.0.0.1 &
SHOT_BASE_URL=http://127.0.0.1:4397 SHOT_OUT_DIR=/tmp/polis-ui-audit/local \
  bun run --filter @polis/apps-web qa:ui
```

Public (light) release world:

```
cd apps/web && PUBLIC_RELEASE=1 PUBLIC_RELEASE_LOCAL_QA=1 \
  PUBLIC_SITE_URL=http://127.0.0.1:4397 bunx astro dev --port 4397 --host 127.0.0.1 &
SHOT_BASE_URL=http://127.0.0.1:4397 SHOT_OUT_DIR=/tmp/polis-ui-audit/public \
  bun run --filter @polis/apps-web qa:ui
```

`astro dev` runs as a background daemon; stop it with `bunx astro dev stop`
from `apps/web` before switching worlds, or the second run silently reuses the
first server.

The rest of the gate:

```
bun run lint
bun run --filter @polis/apps-web typecheck
bun run --filter @polis/apps-web test
bun run --filter @polis/ui test
bun run --filter @polis/apps-web qa:release
```
